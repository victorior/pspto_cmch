- (note) Brownfield: catalogo admin hoy solo alta (tenant_catalog_*); sin edit/delete UI. No existe delete de budget_headers en UI. Permiso anio = tenant_department_edit_policy via UserPermissions::canEditActivityHeader.
- (decision) Slug/workspace: spec-admin-org-y-eliminar-actividades; modo express (input estructurado rico).
- (capability) CAP-1: Super admin crea, edita y elimina centros de costo, divisiones (departments type estandar) y coordinaciones (type coordinacion) del tenant en panel admin.
- (capability) CAP-2: Eliminacion de entidad organica/CC bloqueada si hay actividades de Presupuesto (budget_headers) asociadas; el operador debe eliminar esas actividades antes de poder borrar la entidad.
- (capability) CAP-3: Encargado de division o coordinacion puede eliminar sus propias actividades de Presupuesto cuando el permiso de edicion de ese anio esta activado para su unidad.
- (constraint) Actor catalogo org: solo super admin (sesion admin catalogo existente); no encargados ni tenant_admin para CRUD de CC/divisiones/coordinaciones.
- (constraint) Delete entidad organica/CC: hard block si hay budget_headers asociadas; mensaje claro; sin soft-delete ni cascade que orphanee datos.
- (constraint) Delete actividad (CAP-3): solo propias del encargado (created_by / regla legacy alineada a export); requiere allow_edit=1 (o default vigente) para el anio de la actividad y la unidad de politica.
- (constraint) Scope multi-tenant: operaciones acotadas al tenant_id del contexto admin o portal; no cruzar tenants.
- (constraint) Respetar architecture spine budjetoc (PHP 8 + MySQL multi-tenant; DocumentRoot public/; secretos fuera).
- (decision) Non-goals: no CRUD masivo; no rediseñar replicacion catalogo entre tenants salvo lo necesario para edit/delete coherente; no soft-delete; no eliminar lineas OC con imputacion como sustituto de borrar cabecera; no dar delete de actividades a roles fuera de encargado division/coordinacion salvo decision posterior.
- (assumption) Actividad = budget_headers (+ detalles); no el catalogo de nombres activities.
- (assumption) Asociacion delete-guard: CC = budget_headers.cost_center_id; division = headers con division_id o created_by = esa division; coordinacion = headers con department_id o created_by = esa coordinacion.
- (assumption) Propia actividad = created_by = departments.id de la unidad del encargado (fallback legacy department_id como en BudgetService::filterRowsCreatedByDepartment).
- (assumption) Permiso edicion anio = misma fuente que canEditActivityHeader (tenant_department_edit_policy + defaults por anio).
- (question) Al editar/eliminar CC o departamento en un tenant, debe propagarse a otros tenants (hoy propagate solo en INSERT) o queda local al tenant?
- (question) Si una actividad tiene imputaciones OC (allocations), el delete de cabecera se bloquea como las lineas hoy, o hay otro tratamiento?
- (question) El super admin necesita poder eliminar actividades ajenas/cualquier actividad para desbloquear delete de entidades organicas, o solo encargados (CAP-3) cubren ese prerrequisito?
